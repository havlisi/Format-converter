## 3. Parked review residuals (non-blocking, from this session's final review)

- **F1** — a lone `"31.03."`-style partial date, or a trailing line with a bare decimal
  like `"Zinssatz 3,50 %"`, is treated as amount-bearing and kept in the **last table
  cell** instead of moving to the context text block. Fails safe (no number is displaced
  out of the table). One-line refinement in `_reconstruct_financial_table`'s `elif` guard
  if it ever matters.
- **F3** — in `docx_io.pdf_to_docx`, the root-logger level/handlers are restored **after**
  the `try/except` around `from pdf2docx import Converter`, so if that import itself
  raises, the restore is skipped. Effect: INFO-level log noise on stderr for the rest of
  the process, only in an environment where the PyMuPDF version check fails. `try/finally`
  closes it. `pdf2docx` also emits `WARNING: Ignore Line … due to overlap` during
  `convert()` on some statements — genuine, not surfaced in the GUI.

## 4. Known limitation surfaced by the batch test

**LBBW / Aareal "Liviusfach" export format:** the account header block (Auftraggeber,
IBAN/Institut, Kontoname, Zeitraum, Startsaldo, Endsaldo) is repeated on every page and
gets de-duplicated away — it does **not** reach the XLSX preamble/context block. This is
**pre-existing**, not caused by this session's branch. The footer furniture
(`Kontoinformationen > Konten > …`, `Anzahl: N`, the export timestamp) **is** now
captured. If the recon workflow needs that account header in the sheet, it is a separate
converter task (keep the first occurrence of a repeated-boilerplate line in
`preamble_parts` instead of only recording it for the skip-set).
